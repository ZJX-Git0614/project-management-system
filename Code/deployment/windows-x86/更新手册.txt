Ceastar项目管理系统 Windows x86 离线更新手册
============================================

更新版本：2026.08.04.3（项目级恢复、系统日志、成员多角色与 WBS 负责人联动更新）
适用环境：已安装 Ceastar项目管理系统的 Windows 10/11 x86-64 电脑

一、更新包内容

1. update.bat / update.ps1：自动更新脚本。
2. backup.ps1：新版备份脚本；更新前会先替换旧脚本，保证应用容器崩溃循环时仍可备份文档卷。
3. rollback.bat / rollback.ps1：应用版本回退脚本。
4. images 文件夹：新版 linux/amd64 Docker 镜像。
5. image-name.txt：新版镜像名称。
6. release-id.txt：更新、回退镜像和状态文件共用的发布编号。
7. image.sha256：镜像完整性校验值。
8. release-manifest.txt：镜像平台、源码提交、构建时间和验证结果。
9. Windows-Update-Guide-CN.txt：本手册；使用 ASCII 文件名避免 Windows 解压中文文件名乱码。
10. Database-Migration-Guide-CN.txt / Data-Security-Guide-CN.txt：数据库迁移和数据安全说明。
11. install-mpp-export-service.ps1 / mpp-export-service.ps1：真实 MPP 导出服务安装与运行脚本。

二、更新前准备

1. 确认 Docker Desktop 已启动并显示运行正常。
2. 保证系统盘或 Docker 数据盘至少有 4 GB 可用空间。
3. 将整个“Ceastar-PMS-Update-20260804-3-blue-green”文件夹复制到原部署目录中。
4. 本包是累积更新，兼容 20260803-4 及更早部署的 Compose 配置；不需要补装中间更新包。
5. 如果 0727-3 曾在“Add a /data/system-backups mount”处中止，只要其数据库与文档备份已显示完成，即可直接运行本包，无需再次运行 0727-3。
6. 如需把系统自动备份保存到其他磁盘，可在原部署目录的 .env 文件中增加一行，例如：

PMS_BACKUP_HOST_DIR=D:/Ceastar-PMS-Backups

目标文件夹应提前创建。未配置时继续使用原部署目录下的 backups 文件夹。

正确示例：

D:\PMS\Ceastar-PMS-内网完整部署-20260723\docker-compose.yml
D:\PMS\Ceastar-PMS-内网完整部署-20260723\backup.ps1
D:\PMS\Ceastar-PMS-内网完整部署-20260723\Ceastar-PMS-Update-20260804-3-blue-green\update.bat

更新包文件夹必须与 docker-compose.yml 所在目录相邻，不能再多套一层目录。

三、执行更新

1. 通知正在使用系统的人员先完成并保存当前操作。绿色候选验证期间旧版本仍可访问，但最终切换会短暂重建应用容器。
2. 双击更新包中的 update.bat。
3. 脚本会自动完成以下操作：
   - 检查 Docker Desktop；
   - 校验更新镜像完整性；
   - 备份 PostgreSQL 数据库和上传文档，生成 SHA-256 清单并校验；
   - 保留当前应用镜像作为回退版本；
   - 加载 2026.08.04.3 的 linux/amd64 镜像，并拒绝错误架构的镜像；
   - 使用发布编号 20260804-3 统一生成回退镜像和状态文件；
   - 在 127.0.0.1:3101-3110 中选择一个空闲端口，启动单工作进程的绿色候选容器；
   - 绿色候选容器连接现有 PostgreSQL 与文档卷，执行幂等增量迁移并检查 /login；验证期间原蓝色容器继续在 3000 端口服务；
   - 候选验证通过后删除临时容器，再短暂重建正式 pms 容器完成切换；
   - 候选验证或正式切换失败时，自动恢复更新前镜像；若已经开始切换，还会重建旧容器并重新健康检查；
   - 兼容 Windows CRLF 和旧版 Compose 格式，为旧部署补充备份目录环境变量与挂载，并保留 docker-compose.yml 原文件副本；
   - 不启动 Microsoft Project，也不自动配置 MPP 导出服务，避免 Project 自动化或权限窗口阻塞核心更新；
   - 配置最多 4 个 Web 工作进程，利用多核处理并发请求；
   - 仅重建 pms 应用容器；
   - 检查 http://localhost:3000/login 是否恢复访问。
4. 窗口显示“Ceastar PMS 更新成功”后，按任意键关闭。

更新过程中 PostgreSQL 数据卷、上传文档卷、Ollama 模型和既有备份不会被删除。脚本输出“更新前备份完成并通过校验”时，后面的路径就是本次已校验的更新前备份目录。

数据库迁移说明：

1. 更新前会先导出目标电脑当前 PostgreSQL 数据库和项目文档。
2. 更新包不会导入开发电脑数据库，也不会覆盖目标电脑现有业务数据。
3. 绿色候选容器启动时会执行 prisma/manual-migrations 中的幂等 SQL；本次累计包含模块撤销/重做、事项与风险多重关联、WBS 负责人继承、项目成员唯一性、项目级恢复批次和系统事件日志结构。
4. 数据库迁移失败时绿色候选不会进入就绪状态，正式应用容器不会切换，更新前备份仍保留在原部署目录的 backups 文件夹中。
5. rollback.bat 只回退应用镜像，不删除已迁移的数据，也不会反向删除新增数据库字段。
6. 详细迁移内容见更新包中的 Database-Migration-Guide-CN.txt。

四、更新后检查

1. 打开 http://localhost:3000 并正常登录。
2. 打开项目进度管理，确认任务和甘特图数据仍然存在。
3. 打开项目进度管理，确认 460 条任务滚动流畅；不同任务层级使用不同色标，同一层级颜色保持一致且无斑马纹；任务与甘特图之间的隐藏、展开控件仅显示透明箭头；父任务可单独折叠，“折叠层级”可批量折叠；列宽可拖拽，双击分割线可自动适应内容。
4. 导出 Excel 后修改日期或名称，再重新导入并选择“合并更新”，确认原任务被增量更新而不是重复新增。
5. 重新导入 MPP 文件，确认不再出现 mppjs 退出、AVX2 不支持、path 参数为数字或 Prisma 事务超时；Excel 导入请先点击“下载模板”。
6. 如需导出 Microsoft Project 二进制 MPP 文件，确认更新成功后右键以管理员身份运行 repair-mpp-export-service.bat；该可选操作不影响 Excel 和 Project XML 导出。
7. 打开挣值分析，确认可读取甘特计划、进度、预计工时、实际工时和项目预算关联。
8. 打开文档清单管理，确认上传时可选择服务器本地、公司云盘或双存储。
9. 打开智能助手，上传至少两个进度计划文件（支持 MPP、Project XML、系统模板或普通任务清单 XLSX/CSV、Markdown/TXT），要求佳佳“合并为可导入进度计划”。确认操作后应自动下载 Excel；操作卡片中也可再次点击“下载文件”。
10. 打开下载文件，确认第一张工作表为“项目进度”、任务 ID 按 Task001 开始连续排列，第二张“合并说明”列出源文件、缺失日期回退和未解析依赖；再导入项目进度管理验证。该动作只生成文件，不会直接覆盖现有甘特任务。
11. 打开“系统设置 > 系统数据管理”，在目录选择器中选择容器内的 /data/system-backups，然后保存设置并执行一次手动备份；本地备份最多使用 5 GB，云盘备份最多使用 20 GB。
12. “测试云盘登录”会创建、上传并删除临时测试文件；通过后再执行云盘同步。云盘备份失败时，待办中心应显示数字和告警横幅，并支持一键已读。
13. 如需查看容器状态，在原部署目录打开 PowerShell，执行：

docker compose ps
docker compose logs --tail 100 pms

pms 和 pms-postgres 应显示为运行状态，日志中不应持续出现错误。

14. 打开项目进度管理，进入选择模式后选中任务，确认可使用“上移层级”和“层级下移”；父任务调整层级时全部子任务应同步移动。点击全屏按钮后应可继续直接编辑任务字段。
15. 打开智能助手，确认“佳佳”优先依据本地使用手册回答操作问题，不再承诺系统不存在的能力；Agent 授权可选择“请求批准”“替我审批”“完全访问”，所有模式仍受当前账号权限限制。
16. 打开待办中心，确认历史助手测试产生的待办已清理。迁移只清理本版本发布前由助手生成的历史待办，不删除用户手工创建的真实待办和通知。
17. 打开项目进度管理，确认“负责人”列位于“工期”之前，人员只能从当前项目组成员中选择。
18. 在项目进度管理顶部切换“自然日/工作日”，确认设置对整个项目生效；工作日会跳过中国法定节假日并包含调休工作日，每天按 7.5 小时计算。
19. 修改任务工期，确认预计工时自动按“工期 × 7.5”计算并保留两位小数；设置紧前任务后，后续自动任务的计划日期应随前置任务顺延。
20. 工期支持 0.5 天步进；未填写的工期、预计工时和实际工时显示“--”，点击后再输入实际值，不会被自动补成 1 天或 0 工时。
21. 使用“上移层级”或“层级下移”调整任务后，任务及其子任务的任务类别路径应同步更新；进入全屏后，负责人、紧前任务和列设置等菜单应可正常展开。
22. 打开项目事项管理，确认“关联任务名称”可一次选择多个 WBS 任务，并支持按 WBS 层级展开、折叠和搜索。
23. 打开风险登记册，确认风险只能关联一个或多个项目事项，不提供直接关联 WBS 的入口；点击风险名称旁的明细按钮，可看到关联事项以及由这些事项自动推导的受影响 WBS 任务。
24. 删除一个与风险有关联的事项时，确认框应列出受影响风险；删除后仅移除该事项关联，其余事项关联保留，撤销后原关联恢复。
25. 在项目 WBS 管理中检查负责人：父任务负责人可向子任务继承；不同子任务负责人会汇总到父级；父级汇总超过 2 人时只读；未分配子任务在父级显示提醒。
26. 打开项目事项管理、风险登记册、项目预算管理，确认表格支持右击插入、复制、剪切、粘贴和删除，行内编辑可按 Enter 或点击表格外空白处保存，并支持撤销/重做。
27. 在项目信息管理中确认同一账号不能重复添加，且成员行同时展示该账号当前所有有效角色；账号角色变化后项目页同步更新。
28. 打开“系统设置 > 系统数据管理”，确认“按项目恢复”可选择备份、预检项目与账号映射，恢复成功后保留 30 天保护快照并可回滚。
29. 在同一页确认“系统日志”固定保留 180 天，支持按时间、级别、类别、模块、项目、操作人和关键词筛选，并可导出包含 Excel、JSONL 和说明文件的 ZIP。

五、回退应用版本

如果更新后系统无法正常使用，双击更新包中的 rollback.bat。

回退脚本会先再次备份并校验数据库和上传文档，再在 127.0.0.1 临时端口启动旧版本候选容器。旧版本健康检查通过后才重建正式 pms 容器；任何失败都会恢复回退前正在使用的应用镜像。回退不会删除更新后的数据库数据，也不会反向删除新增表或字段。

六、重要警告

1. 更新时不要运行 install.bat。install.bat 用于首次安装，强制运行可能覆盖现有数据库。
2. 不要执行 docker compose down -v。
3. 不要删除 ceastar-pms_pgdata 和 ceastar-pms_document_storage 数据卷。
4. 不要只复制镜像 tar 文件，必须完整复制整个更新包。
5. 更新成功后，建议将原部署目录下新生成的 backups 文件夹复制到其他磁盘保存。
6. 修改 PMS_BACKUP_HOST_DIR 后，需要在原部署目录执行 docker compose up -d --no-deps --force-recreate pms 使新挂载生效。

七、常见问题

1. 提示 Docker Desktop is not running：启动 Docker Desktop，等待其显示运行正常后重新执行 update.bat。
2. 提示 checksum does not match：先确认使用完整的 20260804-3 更新包。脚本兼容纯哈希和标准 sha256sum 格式，并会显示期望值与实际值。若两者仍不一致，请删除目标电脑上的旧更新包后重新完整复制 ZIP 并解压。
3. 提示 deployment directory was not found：将更新包文件夹直接放到 docker-compose.yml 所在目录中。
4. 页面暂时无法访问：等待 1 至 3 分钟；仍无法访问时执行 docker compose logs --tail 200 pms 查看日志。
5. Ollama 模型是否受影响：不会。更新脚本不修改 Windows 上的 Ollama 安装目录和模型目录。
6. 页面选择不到 D 盘目录：浏览器只能选择容器已挂载目录。请在 .env 中设置 PMS_BACKUP_HOST_DIR=D:/目标目录，重建 pms 容器后，在页面选择 /data/system-backups。
7. 0727-3 提示缺少 /data/system-backups：这是旧脚本兼容问题，备份已完成则数据未受影响；不要重跑旧包，直接使用 2026.08.04.3 累积更新包。
8. 提示缺少 SYSTEM_BACKUP_DIR：本包会同时兼容映射式和列表式 Compose 环境变量，无需再使用 20260728-2a 修复包。
9. MPP 导出仍显示不可用：真实 MPP 写入需要 Windows 安装 Microsoft Project。请在系统更新成功后，右键以管理员身份运行本包中的 repair-mpp-export-service.bat；不要在 update.bat 运行期间执行此脚本。
10. 更新后服务仍起不来并显示 date + double precision：说明仍在使用旧更新包。请使用 2026.08.04.3，该版本已包含半天工期字段的 PostgreSQL 日期运算类型修复。
11. 提示 3101-3110 端口均被占用：关闭占用这些本机临时端口的程序后重新运行。候选端口只绑定 127.0.0.1，不对内网开放。
12. 绿色候选通过后页面为何短暂断开：当前 Windows 部署没有反向代理，最终需要重建一次正式 pms 容器来接管 3000 端口；脚本会在切换后再次健康检查。
13. 在“启动绿色候选环境”处把 Container ... Creating 当作错误：这是 20260803-4 在 Windows PowerShell 5.1 下对 Docker Compose stderr 进度行的误判。正式容器没有切换，已有备份可保留；请直接使用 20260804-3 重新更新，不需要先运行 rollback.bat。
