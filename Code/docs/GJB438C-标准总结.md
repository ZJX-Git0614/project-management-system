# GJB438C《军用软件开发文档编制规范》详细总结

> 编写日期：2026-05-29
> 参考来源：GJB438C-2021（当前最新版，替代 GJB438B-2009）

---

## 一、概述

**GJB438C** 全称《军用软件开发文档编制规范》，是中国国家军用标准，由中央军委装备发展部发布。该标准规定了军用软件开发过程中必须编制的文档种类、内容要素和格式要求。

### 标准定位

| 项目 | 内容 |
|------|------|
| 标准号 | GJB438C-2021 |
| 上级采纳 | 参照 MIL-STD-498（美军标），结合我军装备软件研制实际 |
| 适用范围 | 军用软件研制项目的文档编制、评审和验收 |
| 替代关系 | GJB438B（2009）→ GJB438C（2021） |
| 配套标准 | GJB2786A（军用软件开发通用要求）、GJB5000B（军用软件能力成熟度模型） |

### 核心原则

1. **以文档驱动研制过程**：每个阶段必须有对应的文档输出作为里程碑标志
2. **裁剪原则**：可根据项目规模、类型、关键等级对文档种类进行裁剪
3. **继承性**：文档内容逐层细化，上阶段文档是下阶段工作的依据
4. **可追溯性**：需求→设计→实现→测试，各环节之间保持双向追溯

---

## 二、文档体系（共 27 类文档）

GJB438C 将文档分为三个层级：**系统级**、**软件级**、**单元级**。

### 编号说明

- **S** — System：系统级文档（系统/分系统/配置项）
- **SW** — Software：软件级文档（软件配置项/软件部件）
- **SU** — Software Unit：单元级文档（软件单元）

---

### （一）研制管理类文档（4 类）

| 序号 | 文档编号 | 文档名称 | 英文对照 | 编制时机 |
|------|---------|---------|---------|---------|
| 1 | SPS | 软件研制任务书 | Software Project Specification | 立项阶段 |
| 2 | SDP | 软件开发计划 | Software Development Plan | 计划阶段 |
| 3 | SQAP | 软件质量保证计划 | Software Quality Assurance Plan | 计划阶段 |
| 4 | SCMP | 软件配置管理计划 | Software Configuration Management Plan | 计划阶段 |

**SPS（软件研制任务书）** 核心内容：
- 项目背景与目标
- 技术指标和要求
- 进度和经费约束
- 验收标准和方式
- 承研单位和分工

**SDP（软件开发计划）** 核心内容：
- 项目组织与职责
- 开发过程定义（选用的生命周期模型：瀑布/迭代/增量）
- 里程碑节点和交付物
- 资源估算（人力、设备、工具）
- 风险管理计划
- 培训计划

**SQAP（软件质量保证计划）** 核心内容：
- 质量目标（可靠性、安全性、可维护性等定量指标）
- QA 活动和检查点
- 不符合项处理流程
- 度量和报告机制

**SCMP（软件配置管理计划）** 核心内容：
- 配置项标识规则
- 基线定义（功能基线、分配基线、产品基线）
- 变更控制流程（CCB 组成和裁决机制）
- 配置状态记录和审计

### （二）需求类文档（4 类）

| 序号 | 文档编号 | 文档名称 | 英文对照 | 编制时机 |
|------|---------|---------|---------|---------|
| 5 | SSS | 系统/子系统规格说明 | System/Subsystem Specification | 需求分析 |
| 6 | SRS | 软件需求规格说明 | Software Requirements Specification | 需求分析 |
| 7 | IRS | 接口需求规格说明 | Interface Requirements Specification | 需求分析 |
| 8 | SSUM | 系统/子系统需求说明（C 版新增） |  | 需求分析 |

**SSS（系统/子系统规格说明）** 核心内容：
- 系统功能分解
- 各分系统的功能需求、性能需求
- 系统外部接口
- 系统级约束条件
- 关键技术指标（KTI）

**SRS（软件需求规格说明）** 核心内容（最重要文档之一）：
- 软件功能需求（用例/功能列表）
- 软件性能需求（响应时间、吞吐量、容量）
- 接口需求（外部接口、内部接口、人机接口）
- 数据需求（数据字典、数据结构）
- 安全保密需求
- 可靠性/可用性/可维护性需求
- 环境需求（硬件平台、OS、第三方软件）
- 需求优先级和关键等级

**IRS（接口需求规格说明）** 核心内容：
- 接口标识和类型
- 接口数据格式（消息格式、协议）
- 接口时序要求
- 接口错误处理

### （三）设计类文档（4 类）

| 序号 | 文档编号 | 文档名称 | 英文对照 | 编制时机 |
|------|---------|---------|---------|---------|
| 9 | SDD | 软件设计说明 | Software Design Description | 概要/详细设计 |
| 10 | IDD | 接口设计说明 | Interface Design Description | 详细设计 |
| 11 | DBDD | 数据库设计说明 | Database Design Description | 详细设计 |
| 12 | SArD | 软件体系结构设计说明（C 版新增） | Software Architecture Description | 概要设计 |

**SDD（软件设计说明）** 核心内容（核心文档之一）：
- 体系结构设计（模块分解、层次结构）
- 模块描述（每个模块的功能、输入、输出、处理逻辑）
- 全局数据设计
- 容错/安全设计
- 设计约束和权衡分析
- CSCI → CSC → CSU 的逐级分解

**IDD（接口设计说明）** 核心内容：
- 接口详细设计（数据结构、消息序列）
- 接口控制规范
- 人机界面设计

**DBDD（数据库设计说明）** 核心内容：
- 数据库概念模型（E-R 图）
- 数据库逻辑设计（表结构、索引、视图）
- 数据库物理设计（存储分配、访问方式）
- 数据完整性和安全性设计

### （四）测试类文档（3 类）

| 序号 | 文档编号 | 文档名称 | 英文对照 | 编制时机 |
|------|---------|---------|---------|---------|
| 13 | STP | 软件测试计划 | Software Test Plan | 编码前 |
| 14 | STD | 软件测试说明 | Software Test Description | 测试准备 |
| 15 | STR | 软件测试报告 | Software Test Report | 测试完成 |

**STP（软件测试计划）** 核心内容：
- 测试策略和方法（单元测试/集成测试/确认测试/系统测试）
- 测试用例设计原则
- 测试环境要求
- 测试通过准则
- 测试进度和资源

**STD（软件测试说明）** 核心内容：
- 每个测试用例的详细说明（输入、步骤、预期结果）
- 测试数据准备

**STR（软件测试报告）** 核心内容：
- 测试执行情况总结
- 测试结果分析
- 缺陷统计和分类
- 测试结论（是否通过）

### （五）交付验收类文档（5 类）

| 序号 | 文档编号 | 文档名称 | 英文对照 | 编制时机 |
|------|---------|---------|---------|---------|
| 16 | SPS | 软件产品规格说明 | Software Product Specification | 验收交付 |
| 17 | SVD | 软件版本说明 | Software Version Description | 版本发布 |
| 18 | SUM | 软件用户手册 | Software User Manual | 验收前 |
| 19 | SIOM | 软件输入/输出手册 | Software Input/Output Manual | 验收前 |
| 20 | SCOM | 软件中心操作员手册 | Software Center Operator Manual | 验收前 |

**SPS（软件产品规格说明）** 核心内容：
- 可执行程序清单
- 源文件清单
- 编译/构建脚本和步骤
- 运行环境要求
- 安装和卸载说明
- 设计约束最终确认

**SVD（软件版本说明）** 核心内容：
- 版本号规则
- 本版新增/修改/修复功能列表
- 已知问题清单
- 交付媒体列表
- 安装说明

**SUM（软件用户手册）** 核心内容：
- 软件概述和功能说明
- 操作环境要求
- 安装和启动步骤
- 各功能操作指南（分步骤截图）
- 故障排除指南
- 常用命令/快捷键参考

| 序号 | 文档编号 | 文档名称 | 英文对照 | 编制时机 |
|------|---------|---------|---------|---------|
| 21 | SDSR | 软件开发总结报告 | Software Development Summary Report | 项目结束 |
| 22 | SQAR | 软件定型测评报告 | Software Qualification Assessment Report | 定型阶段 |

| 24 | SIP | 软件安装计划 | Software Installation Plan | 交付前 |

**SDSR（软件开发总结报告）** 核心内容：
- 项目完成情况总结
- 实际进度与计划对比
- 实际工作量统计
- 技术指标达标情况
- 经验和教训

**SQAR（软件定型测评报告）** 核心内容：
- 测评范围和依据
- 测评环境和工具
- 功能性测评结果
- 可靠性/安全性测评结果
- 综合评价结论

### （七）C 版新增文档（3 类）

与 GJB438B 相比，GJB438C 新增了以下文档：

| 文档编号 | 文档名称 | 用途说明 |
|---------|---------|---------|
| SArD | 软件体系结构设计说明 | 专门描述架构设计，与详细设计分离 |
| SSUM | 系统/子系统需求说明 | 明确系统级需求归属 |
| — | 软件安全性保证计划 | 针对安全关键软件的专项计划 |

## 三、GJB438C vs GJB438B 主要变化

| 对比项 | GJB438B（2009） | GJB438C（2021） |
|--------|----------------|----------------|
| 文档总数 | 24 类 | 27 类 |
| 架构设计 | 归入 SDD | 新增 SArD 独立成册 |
| 安全性要求 | 一般提及 | 专项计划/独立章节 |
| 敏捷开发 | 未覆盖 | 增加了剪裁指南 |
| 术语统一 | 与 MIL-STD-498 一致 | 与 GJB2786A、GJB5000B 对齐 |
| 文档模板 | 固定格式 | 提供了更灵活的模板结构 |
| 数据要求 | 传统文档描述 | 增加了数据字典标准化要求 |

## 四、与软件生命周期模型的对应关系

### 瀑布模型下的文档编制矩阵

```
┌─────────────────────────────────────────────────────┐
│  阶段          │  输入文档    │  输出文档            │
├─────────────────┼──────────────┼──────────────────────┤
│  立项          │  研制总要求  │  SPS                 │
│  需求分析      │  SPS         │  SRS, IRS, SSS       │
│  概要设计      │  SRS         │  SArD, IDD, DBDD     │
│  详细设计      │  SArD        │  SDD, IDD (细化)     │
│  编码实现      │  SDD         │  源代码, SPS (初稿)  │
│  测试          │  STP, STD    │  STR                 │
│  验收交付      │  各文档终版  │  SUM, SVD, SDSR      │
│  维护          │  所有文档    │  变更记录            │
└─────────────────────────────────────────────────────┘
```

### 迭代/敏捷模式下的剪裁建议

GJB438C 不强制要求所有文档全量编制，允许：
- **合并文档**：小型项目可将 SDP/SQAP/SCMP 合并为"软件研制计划"
- **简化文档**：非安全关键等级的 CSCI 可简化 SRS 和 SDD
- **迭代编制**：文档随迭代逐版更新，不要求一次性完稿
- **工具生成**：部分内容可从需求管理工具/设计工具自动导出

## 五、与其它标准的关系

| 标准 | 关系说明 |
|------|---------|
| **GJB2786A** | 软件开发通用要求，定义"做什么"；GJB438C 定义"写什么" |
| **GJB5000B** | 软件能力成熟度模型，定义过程能力；GJB438C 是文档实践的具体产出物 |
| **GJB9001C** | 质量管理体系要求；GJB438C 的文档体系是质量证据 |
| **GB/T 8567** | 国家推荐标准《计算机软件文档编制规范》；GJB438C 是其军用升级版 |
| **MIL-STD-498** | 美军标；GJB438B/C 大量借鉴其文档分类框架 |

## 六、文档编制注意事项

### 常见问题（评审中高频扣分项）

1. **需求追溯矩阵缺失或不完整**
   - 每条软件需求必须追溯到系统需求
   - 每条设计必须追溯到需求
   - 每个测试用例必须追溯到需求

2. **接口定义不清晰**
   - 接口双方的职责要明确（谁发送、谁接收、数据格式由谁定义）
   - 接口变更要双向同步

3. **测试覆盖不充分**
   - 未覆盖所有功能需求
   - 未覆盖边界条件和异常路径
   - 未覆盖安全性/可靠性需求

4. **版本混乱**
   - 文档版本与软件版本不一致
   - 修改后未更新变更记录

5. **文档之间矛盾**
   - SRS 和 SDD 中对同一功能的描述不一致
   - 接口需求和接口设计对不上

## 七、总结

GJB438C 是当前我国军用软件开发领域最权威、最通用的文档编制规范。它继承了 MIL-STD-498 的优点，同时针对我军装备软件研制的特点和经验进行了本地化适配。C 版相对于 B 版最显著的变化是增加了架构设计文档（SArD），提升了安全性要求，并初步回应了敏捷开发模式的需求。

对于军用软件项目和系统集成项目（如本项目的 Ceastar项目管理系统），GJB438C 的核心价值在于提供了一个**标准化的文档框架**，确保项目的需求、设计、实现、测试各环节有据可查、可追溯。实际贯彻时，建议根据项目关键等级合理剪裁，重点关注 SRS、SDD、STP/STR 和 SUM 这四件核心文档。
