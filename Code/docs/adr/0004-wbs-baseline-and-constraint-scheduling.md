# WBS 基线、边界与资源约束排期

WBS 的计划字段分为自动排程、工期固定正排、工期固定倒排和日期固定四种计算方式。自动排程任务可在项目日历、FS 紧前关系、父级硬边界及负责人容量约束内移动；其余三类任务是用户输入的硬约束，只能生成影响分析和可应用方案，不能被系统静默改期。

拥有子任务的父任务是汇总节点，不消耗负责人容量或直接维护实际工时。未锁定时，父任务日期由后代任务汇总；用户将父任务配置为开始、完成或完整边界后，该窗口成为后代必须遵守的硬边界。项目可另行设置合同硬完成边界，违反任一硬边界即阻止基线发布。

本期依赖只支持 FS 与非负半日时差。关键路径只基于依赖、日期边界、计划/实际完成时间计算；资源关键链独立计算，不伪造为业务依赖。虚线只表示浮动时间。

计划首次发布及每次变更发布均生成不可变基线版本。发布后，计划字段和 WBS 结构冻结；仅实际开始、实际完成、实际工时与当前进度可更新。变更通过单一活动草案完成，草案的预览在实际数据变化后必须失效并重新计算。只有当前项目经理可以发布或发布变更，拥有单独草案权限的成员可以准备草案。

## Consequences

- 任务模式、父级边界、项目硬边界、基线版本和草案状态必须以结构化字段持久化，不能依赖自由文本或前端状态。
- 现有历史任务、依赖和负责人分配必须兼容读取；不支持的非 FS 依赖保留原始数据并阻止自动排期或基线发布。
- 叶子任务只允许一名直接负责人；父任务负责人由后代汇总并只读。已有多人叶子分配保留为历史数据，升级后需要显式修复后才可发布新基线。
- 所有影响排期的写入都必须经过服务端校验，并返回可展示的冲突、影响范围和候选方案。
