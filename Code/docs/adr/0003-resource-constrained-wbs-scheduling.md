# WBS 单一正式自动排期

## Decision

WBS 只保留一个可应用的正式自动排期算法。日常新增、编辑、导入、负责人变更和刷新只更新父级汇总、实际汇总、CPM 指标、关键路径及派生优先级，绝不自动移动任何叶子任务的计划开始、计划完成、工期或负责人。

正式自动排期必须由用户在 WBS 中明确发起，或由智能助手生成经确认的操作提案后发起。预览与应用共用同一份版本化快照；快照、WBS 修订号或约束变化后，旧预览不能再写入。

## Algorithm

1. 以项目 T0、工作日历、已确认的 FS 紧前关系、锁定父级边界和项目硬完成日期建立末级执行网络。父任务的自动汇总日期是结果，不是叶子任务的排期锚点。
2. 先忽略负责人容量计算 CPM，得到初始总浮动、下游工作量和关键路径。
3. 对未开始且允许自动排期的末级任务按“总浮动小 -> 下游影响大 -> 业务优先级高 -> WBS 顺序”稳定排序。同一负责人串行，不同负责人可并行；已完成、进行中、日期固定、范围外任务作为不可移动占用。
4. 在每位负责人的可用工作日历中安排任务。锁定父级和项目硬完成日期属于硬约束，不能穿透；目标日期只产生风险预警，不伪造不可行日期。
5. 对资源安排后的结果重新计算 CPM、关键路径和浮动，生成一份“正式自动排期”预览，列出日期变化、资源约束、关键路径变化、边界冲突及剩余问题。
6. 只有不存在阻断问题且用户确认应用时才写入任务计划日期。工期、负责人、紧前关系和硬边界不会被静默修改。

当前正式求解仅支持 FS 关系。依赖链末级任务缺少已确认工期、唯一负责人、有效排期锚点、存在循环依赖或突破硬边界时，系统只给出问题与可应用方案，不生成部分或虚假的计划。

## Consequences

- “普通重算”不再是一个可改变计划的功能。它保留为兼容旧接口的派生数据刷新路径。
- 排期结果必须通过预览、确认、审计和通知闭环；用户可清楚区分手工数据与系统正式排期结果。
- 父级日期只有在 `ROLLUP` 模式下由后代汇总；`TARGET` 是预警窗口，`LOCKED` 是硬边界。
- 负责人资源约束不会写回紧前任务字段，业务依赖与人员容量始终分离。
