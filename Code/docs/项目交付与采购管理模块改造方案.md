## 1. 需求范围与本次设计结论

### 1.1 要新增的模块

系统新增两个项目级模块：

```text
项目交付管理
├── 交付物清单
└── 交付物状态管理

项目采购管理
└── BOM / 线缆清单同步后的采购执行管理
```

### 1.2 已确认的业务需求

**交付物清单**以表格维护，必须包含：

- 名称
- 数量
- 单位
- 类型：软件、硬件
- 是否外协：是、否、部分

**交付物状态管理**按交付物类型展示不同信息：

- 软件：必须登记代码版本 Git 地址。
- 硬件：可选择是否有样机；样机与量产机分别上传 BOM 清单、线缆清单。

**项目采购管理**：

- 由已发布的硬件 BOM/线缆清单生成采购需求。
- 管理采购数量、单位、金额及采购过程状态。

### 1.3 关键设计决策

| 决策 | 设计结论 | 原因 |
| --- | --- | --- |
| BOM 是否只作为附件 | 否。附件保留，同时导入为结构化 BOM 行 | 只有可计算、可追踪的物料行才能同步成采购条目 |
| 交付物与状态是否拆表 | 是。交付物清单存合同/范围事实，状态表存进展和类型专属信息 | 使“清单”稳定、“状态”可持续更新，职责清晰 |
| 软件 Git 记录内容 | Git 地址必填；Tag/分支/Commit 可选但建议填写 | Git 地址说明仓库位置，版本标识才能保证可复现 |
| 样机信息如何影响资料要求 | 选择“有样机”后，样机 BOM 和样机线缆清单成为必填；量产资料始终按量产范围管理 | 避免没有样机的项目被迫填写无意义资料 |
| BOM 变更后如何影响采购 | 不静默覆盖。先生成新版本，再显示差异预览后同步 | 已询价、已下单或已收货的采购数据必须保留历史 |
| 采购条目来源 | 支持 BOM、线缆清单、手工新增三种来源 | 既保证技术物料可追溯，也覆盖临时采购与外协服务 |
| 采购状态如何记录 | 当前状态 + 不可覆盖的状态变更记录 | 既方便当前跟进，也能回看采购过程 |

## 2. 项目闭环与模块关系

新增模块不应独立存在，而应嵌入现有项目闭环。

```text
项目成员与权限
    ↓
项目基本信息 ──► 交付物清单 ──► 交付物状态管理
                                │
                                ├── 软件：Git 地址 / 版本标识
                                │
                                └── 硬件：样机、量产 BOM/线缆清单
                                               ↓ 发布版本
                                      BOM / 线缆结构化物料行
                                               ↓ 同步预览
                                      项目采购管理（采购条目）
                                               ↓
                         采购状态、到货、检验、金额、供应商
                                               ↓
                       执行阶段 Gate / 项目文档 / 事项与风险 / 审批
```

### 2.1 与现有模块的衔接

| 现有模块 | 新模块的衔接方式 | 目的 |
| --- | --- | --- |
| 项目信息与成员 | 全部新记录绑定 `projectId`；负责人、采购经办人从项目成员中选择 | 保证项目边界和责任人一致 |
| 项目 WBS | 交付物和采购条目可选关联 WBS 任务；硬件到货可成为任务推进依据 | 让交付/采购不脱离计划 |
| 项目执行驾驶舱与 Gate | Gate 可检查关键交付物是否验收、关键物料是否到货/合格 | 阶段放行有客观证据 |
| 项目文档 | BOM、线缆清单复用项目文件存储与 WebDAV 能力 | 不新建第二套文件系统 |
| 项目预算 | 采购条目可关联预算中的采购型条目；采购金额用于预算偏差对照 | 把采购执行与经营控制连接起来 |
| 项目事项与风险 | 缺料、延期、检验不合格可一键或手工转为事项/风险 | 形成问题闭环和预警 |
| 审批中心 | 交付物验收、重要 BOM 发布、金额阈值以上下单可接入现有流程 | 关键决策有授权、有记录 |
| 协同沟通 | 围绕交付物、BOM 版本和采购条目发起主题并上传附件 | 讨论不脱离具体业务对象 |
| 操作日志、备份与恢复 | 新表纳入项目恢复、系统备份、操作日志和模块历史 | 数据可审计、可恢复 |

## 3. 信息架构与页面入口

### 3.1 侧边栏结构

在已选择项目时新增两个一级分组：

```text
项目范围管理
└── 文档清单管理（已有）

项目交付管理（新增）
├── 交付物清单
└── 交付物状态管理

项目采购管理（新增）
└── 项目采购管理
```

沿用现有项目详情的 `?nav=` 形式，建议入口为：

| 菜单项 | 建议 URL | 权限查看键 |
| --- | --- | --- |
| 交付物清单 | `/projects/{projectId}?nav=deliverables` | `project-deliverables:view` |
| 交付物状态管理 | `/projects/{projectId}?nav=delivery-status` | `project-delivery-status:view` |
| 项目采购管理 | `/projects/{projectId}?nav=procurement` | `project-procurement:view` |

未选择项目时不显示这些菜单项，保持现有“先选项目、再操作项目模块”的交互逻辑。

### 3.2 页面通用交互要求

新模块必须继承当前 `DESIGN.md` 的项目操作界面规则：

- 使用现有深色、紧凑、可扫描的表格界面，不引入营销化卡片布局。
- 使用共享 `Table`、`Dialog`、`Select`、`Badge`、`Tooltip` 等组件。
- 行级结构操作使用既有右键菜单语言；不在表格中固定占用“操作”列。
- 新建或编辑行按 Enter 或离开编辑区域保存，Escape 取消；必填字段不完整时保持编辑状态并给出行内提示。
- 每个可编辑模块提供独立的撤销、重做按钮和快捷键支持；采购状态变更日志不受撤销覆盖。
- 文件上传、删除、BOM 发布、同步采购和删除业务对象都必须使用明确的确认文案。
- 空状态要说明下一步，例如“请先创建硬件交付物，再上传 BOM 或线缆清单”。

## 4. 模块一：交付物清单

### 4.1 模块目的

用一张稳定的项目范围表定义“本项目最终要交付什么”。它是交付状态、技术资料、采购来源、验收和项目文档的共同主对象。

### 4.2 表格字段

| 字段 | 类型/取值 | 必填 | 规则 |
| --- | --- | --- | --- |
| 序号 | 系统生成 | 是 | 用于排序与批量结构操作 |
| 交付物名称 | 文本 | 是 | 同一项目内建议唯一；删除前检查关联状态、BOM 和采购条目 |
| 数量 | 大于 0 的数值 | 是 | 交付总量；硬件还会在状态管理中拆分样机/量产数量 |
| 单位 | 文本或受控下拉 | 是 | 例如：套、台、件、项、版、许可 |
| 类型 | `软件` / `硬件` | 是 | 决定状态管理显示的软件或硬件字段 |
| 是否外协 | `否` / `是` / `部分` | 是 | 表示交付责任边界，并同步显示在采购条目来源信息中 |
| 当前状态 | 只读状态标签 | 否 | 从交付物状态管理读取，便于清单快速浏览 |
| 关联 WBS | 可选 | 否 | 可关联一个或多个 WBS 叶子任务；首期可先支持单任务关联 |
| 备注 | 长文本 | 否 | 补充范围或特殊约束 |

用户明确要求的五个字段为首期最小必备字段；“当前状态、关联 WBS、备注”用于让清单进入项目闭环，不改变最小字段含义。

### 4.3 可执行操作

- 新增、编辑、排序、复制、剪切、粘贴、删除交付物。
- 按类型、外协方式、当前状态、关键字筛选。
- 导出为 CSV/XLSX（首期可先 CSV）。
- 点击某行进入或定位到对应的“交付物状态管理”记录。
- 有已同步采购条目时，不允许物理删除交付物；改为“作废/归档”并保留历史关联。

### 4.4 类型切换规则

- `软件 → 硬件`：必须确认，因为会清空或归档 Git 专属字段，并初始化硬件状态资料。
- `硬件 → 软件`：若存在 BOM、线缆清单或已同步采购条目，则禁止直接切换；需先将硬件交付物作废并新建软件交付物。
- 已进入“已交付”或“已取消”状态的交付物不可直接修改类型、数量和外协方式，需先按权限重新打开或发起变更。

## 5. 模块二：交付物状态管理

### 5.1 模块目的

针对交付物类型管理当前进展、验收准备情况和技术依据。清单回答“交付什么”，状态管理回答“交付到哪一步、凭什么证明”。

### 5.2 通用状态流

```text
草稿 DRAFT
    ↓
进行中 IN_PROGRESS
    ↓
待评审 READY_FOR_REVIEW
    ├── 退回 REJECTED ──► 进行中 IN_PROGRESS
    └── 验收通过 ACCEPTED
                         ↓
                    已交付 DELIVERED

草稿 / 进行中 / 待评审 ──► 已取消 CANCELLED
```

状态含义：

| 状态 | 含义 | 关键校验 |
| --- | --- | --- |
| 草稿 | 已在范围中登记，尚未正式开始准备 | 无 |
| 进行中 | 正在研发、制作或准备交付 | 无 |
| 待评审 | 交付资料已齐，可申请评审/验收 | 执行类型专属必填校验 |
| 验收通过 | 已完成技术/管理验收 | 如配置审批流程，则以审批通过为准 |
| 已交付 | 已向客户、内部下一阶段或指定接收方完成交接 | 必须先验收通过 |
| 退回 | 评审未通过，需要补充或修改 | 必填退回说明 |
| 已取消 | 经确认不再交付 | 必填取消原因 |

### 5.3 软件交付物状态字段

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 当前状态 | 是 | 使用通用状态流 |
| 代码版本 Git 地址 | 是 | 支持 HTTPS 或 SSH 格式；系统不保存 Git 账号或密钥 |
| 版本标识 | 建议 | Tag、分支或 Commit SHA，保证提交版本可定位 |
| 构建/发布说明 | 否 | 记录部署包、环境或版本差异 |
| 验收说明 | 待评审后建议 | 记录测试结论、接收方或退回原因 |

软件交付物尝试进入“待评审”时，若未填写 Git 地址，系统阻止提交并提示补齐“代码版本 Git 地址”。

### 5.4 硬件交付物状态字段

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 当前状态 | 是 | 使用通用状态流 |
| 是否有样机 | 是 | `是` / `否`；决定样机资料是否必须 |
| 样机数量 | 有样机时必填 | 大于 0；与量产数量合计不得超过交付物总数量 |
| 量产数量 | 是 | 大于等于 0；无样机时默认等于交付物总数量 |
| 样机 BOM 清单 | 有样机时必填 | 需要上传文件并导入/维护结构化物料行 |
| 样机线缆清单 | 有样机时必填 | 需要上传文件并导入/维护结构化线缆行 |
| 量产 BOM 清单 | 是 | 需要上传文件并导入/维护结构化物料行 |
| 量产线缆清单 | 是 | 需要上传文件并导入/维护结构化线缆行 |
| 验收说明 | 待评审后建议 | 记录检验、试装、测试或交接结论 |

进入“待评审”的硬件交付物必须符合以下规则：

1. 已选择“有样机”时，样机 BOM 和样机线缆清单均已存在有效版本；
2. 量产 BOM 和量产线缆清单均已存在有效版本；
3. 样机数量与量产数量的合计等于交付物清单中的数量；无样机时量产数量等于交付物清单中的数量；
4. 待采购物料如影响交付，应在采购模块中没有处于“暂停、检验不合格、已取消”的关键未闭环记录。

### 5.5 硬件资料卡片布局

状态管理列表点击硬件交付物后，在右侧抽屉或详情弹窗中展示以下四张资料卡：

```text
样机（仅“有样机”时显示）
├── BOM 清单：当前版本、上传、导入、查看物料行、发布采购源
└── 线缆清单：当前版本、上传、导入、查看物料行、发布采购源

量产机
├── BOM 清单：当前版本、上传、导入、查看物料行、发布采购源
└── 线缆清单：当前版本、上传、导入、查看物料行、发布采购源
```

每张卡都显示文件名、版本号、上传人、上传时间、发布状态、已同步采购数量和差异提示。

## 6. BOM 与线缆清单：从附件到可采购数据

### 6.1 为什么必须结构化

只上传 Excel/PDF 文件无法可靠得到采购数量、单位和金额。为实现“BOM 清单同步到项目采购管理”，每份 BOM 或线缆清单必须同时具备：

1. **原始附件**：用于技术依据、审计和下载；
2. **结构化物料行**：用于计算需求数量、生成采购条目和追踪变更。

### 6.2 BOM/线缆版本模型

一个硬件交付物按“阶段 × 清单类型”分别维护版本：

| 阶段 | 清单类型 | 示例 |
| --- | --- | --- |
| 样机 | BOM | 样机 BOM V1、样机 BOM V2 |
| 样机 | 线缆清单 | 样机线缆 V1 |
| 量产 | BOM | 量产 BOM V1、量产 BOM V2 |
| 量产 | 线缆清单 | 量产线缆 V1 |

版本状态为：

```text
草稿 DRAFT ──► 已发布为采购源 RELEASED ──► 已被新版本替代 SUPERSEDED
```

- 草稿可反复导入、编辑、删除物料行。
- 已发布版本不可直接修改；任何内容变更生成新版本。
- 只有 `RELEASED` 版本能同步到采购管理。
- 新版本发布后，旧版本继续保留，以便解释已下单物料来自哪版技术资料。

### 6.3 结构化导入模板

首期支持 CSV/XLSX 导入。推荐统一模板列如下：

| 列名 | 是否必填 | 用途 |
| --- | --- | --- |
| 物料编码 | 建议 | 合并、去重和与 ERP 对接的稳定键 |
| 物料名称 | 是 | 采购名称 |
| 规格型号 | 建议 | 避免同名物料采购错误 |
| 单位 | 是 | 件、米、套等 |
| 单台/单套用量 | 是 | 大于 0；与样机/量产数量相乘得到采购需求 |
| 厂家/品牌 | 否 | 选型约束 |
| 参考供应商 | 否 | 询价参考 |
| 备注 | 否 | 替代料、特殊工艺、交期说明等 |

导入流程：

1. 上传原始 BOM 或线缆清单文件；
2. 选择“导入为结构化清单”；
3. 显示列映射与预览，标出空名称、非法数量、缺少单位和重复物料；
4. 用户确认后生成草稿版本和物料行；
5. 用户检查后发布为采购源；
6. 从发布版本发起“同步到项目采购管理”。

PDF、图片或无法识别的旧格式文件可作为附件保留，但首期不做 OCR 自动拆料；需要按模板导入或手工补录物料行，防止错误采购。

### 6.4 需求数量计算

```text
采购需求数量 = 清单中单台/单套用量 × 对应阶段的交付数量
```

示例：量产机数量为 100 台，BOM 中某连接器单台用量为 2 件，则第一次同步的建议采购数量为 200 件。

样机与量产物料分别同步，采购条目始终记录来源阶段和来源清单类型，避免把样机试制物料与量产物料混在一起。

## 7. 模块三：项目采购管理

### 7.1 模块目的

管理项目需要买什么、从哪一版 BOM 来、谁负责采购、目前买到哪一步、实际花了多少钱，以及物料是否已经到货并验收合格。

### 7.2 采购条目来源

| 来源 | 创建方式 | 追溯方式 |
| --- | --- | --- |
| BOM | 从已发布的 BOM 版本同步 | 交付物、样机/量产、BOM 版本、物料行 |
| 线缆清单 | 从已发布的线缆清单同步 | 交付物、样机/量产、线缆版本、物料行 |
| 手工新增 | 项目采购管理中新增 | 标注“手工采购”，可选关联 WBS、预算和交付物 |

### 7.3 采购管理表格字段

| 分组 | 字段 | 说明 |
| --- | --- | --- |
| 来源追溯 | 交付物、阶段、来源清单、BOM 版本、物料编码 | 由同步带入，原则上只读 |
| 物料信息 | 物料名称、规格型号、品牌/厂家、备注 | 可在未下单前补充 |
| 数量单位 | 计划采购数量、已下单数量、已到货数量、合格数量、单位 | 同时展示计划与实际，支持部分到货 |
| 金额 | 含税单价、计划金额、订单金额、实际金额、币种 | 计划金额可由数量 × 单价计算；实际金额可在下单/结算时更新 |
| 采购过程 | 当前状态、采购经办人、供应商、采购申请号、订单号 | 便于责任跟踪和对账 |
| 时间 | 申请日期、预计到货日期、实际到货日期 | 用于交期预警 |
| 项目关联 | 关联 WBS、关联预算条目、外协方式 | 连接计划、成本与范围 |

### 7.4 采购状态流

```text
草稿 DRAFT
    ↓
待采购 PENDING_PURCHASE
    ↓
寻源/询价 SOURCING
    ↓
已下单 ORDERED
    ↓
部分到货 PARTIALLY_RECEIVED ──► 已到货 RECEIVED
                                      ↓
                                  检验中 INSPECTING
                                  ├── 合格 ACCEPTED ──► 已关闭 CLOSED
                                  └── 不合格 REJECTED ──► 寻源/询价 或 已取消

除已关闭外，受权限控制可置为暂停 ON_HOLD；
草稿、待采购、寻源/询价阶段可取消 CANCELLED。
```

状态定义：

| 状态 | 业务含义 | 最低更新要求 |
| --- | --- | --- |
| 草稿 | 刚同步或手工创建，尚未确认是否采购 | 来源和计划数量存在 |
| 待采购 | 已确认需要采购，等待经办处理 | 采购经办人 |
| 寻源/询价 | 正在询供应商、比价或定价 | 可填写候选供应商与报价说明 |
| 已下单 | 已形成正式订单 | 供应商、订单号、下单数量、订单金额、预计到货日期 |
| 部分到货 | 已到货数量小于下单数量 | 已到货数量、实际到货日期 |
| 已到货 | 已完成全部到货 | 已到货数量达到下单数量 |
| 检验中 | 正在做来料或功能检验 | 检验负责人/说明 |
| 合格 | 检验通过，可用于项目 | 合格数量与结论 |
| 不合格 | 检验失败，需要退货、补货或替代 | 不合格原因、处置说明 |
| 已关闭 | 采购完成且无待处理问题 | 允许归档，不再常规编辑 |
| 暂停/已取消 | 采购暂缓或终止 | 必填原因 |

### 7.5 数量与金额规则

- `计划采购数量`由 BOM/线缆同步时生成，手工条目由用户填写。
- `已下单数量`、`已到货数量`、`合格数量`均不得为负数。
- `已到货数量`不应超过已下单数量；确有超收时必须确认并记录原因。
- `计划金额 = 计划采购数量 × 含税单价`；未填写单价时显示“待询价”。
- `订单金额`、`实际金额`允许与计划金额不同，但必须保留差异和原因。
- 采购条目可关联现有采购型预算条目，用于识别预算超支或节余。

### 7.6 BOM 同步设计

“同步到项目采购管理”不是简单复制，而是一次可预览、可追溯的业务动作。

```text
已发布 BOM/线缆版本
        ↓
计算阶段需求数量
        ↓
差异预览（新增 / 数量变化 / 规格变化 / 已无来源）
        ↓
用户确认同步
        ↓
创建或更新可安全变更的采购条目
        ↓
记录来源版本和同步结果
```

同步规则：

1. 首次同步：每个结构化物料行创建一条采购条目，状态为 `DRAFT`。
2. 再次同步：按“交付物 + 阶段 + 清单类型 + 物料编码/名称规格”匹配现有采购条目。
3. 采购条目仍在 `DRAFT`、`PENDING_PURCHASE` 或 `SOURCING` 时，允许在确认预览后更新计划数量和来源版本。
4. 已下单、已到货或已检验的条目不可被 BOM 同步静默改写；差异显示为“待处理变更”，由用户新增差量采购、保留原条目或发起变更审批。
5. BOM 删除某行不会自动取消已下单采购；同步预览仅提示“来源已移除”。
6. 首期支持在同步弹窗中选择“仅 BOM”“仅线缆清单”或“两者都同步”。
7. 每个采购条目记录来源交付物、样机/量产阶段、来源版本与来源行，支持一键回溯。

### 8.3 关系与删除策略

```text
Project
 ├── ProjectDeliverable
 │    ├── ProjectDeliverableStatus (1:1)
 │    └── ProjectMaterialRevision
 │         └── ProjectMaterialItem
 └── ProjectProcurementItem
      └── ProjectProcurementStatusLog

ProjectMaterialItem ──可追溯关联──► ProjectProcurementItem
ProjectDocumentFile ──被版本记录引用──► ProjectMaterialRevision
```

- 删除项目时，新增实体随项目级外键级联删除，符合当前项目恢复/备份边界。
- 删除交付物前检查是否有已发布版本或采购条目；有历史时改为作废/归档，不物理删除。
- 删除材料版本前检查是否已同步采购；已同步时只允许“标记替代”，不删除来源记录。
- 删除采购条目仅允许 `DRAFT` 或 `PENDING_PURCHASE`；其他状态改为取消并记录原因。

### 9.1 权限树建议

| 模块 | 查看 | 操作权限 |
| --- | --- | --- |

权限命名、菜单隐藏和服务端校验均遵循现有 `permissions.ts`、侧边栏和 API 鉴权模式。仅隐藏菜单不构成权限控制，所有写接口必须再次校验项目访问权和具体操作权限。

### 9.2 审批接入策略

首期复用现有审批中心与可配置流程，不硬编码某个组织的审批人。建议新增三个可配置业务事件：

| 事件 | 触发时机 | 默认建议 |
| --- | --- | --- |
| `DELIVERABLE_ACCEPTANCE` | 交付物从待评审进入验收通过 | 启用；无流程配置时由拥有状态变更权限的用户处理 |
| `MATERIAL_REVISION_RELEASE` | BOM/线缆草稿发布为采购源 | 可选，用于受控技术变更项目 |
| `PROCUREMENT_ORDER_APPROVAL` | 采购条目从寻源/询价进入已下单 | 按金额阈值或项目类型配置 |

审批通过后才落最终状态；退回或拒绝将业务对象保留在可修改状态，并同步保留审批意见。

### 9.3 协同、事项与风险

- 交付物、BOM 版本和采购条目详情页提供“发起协同”入口，主题绑定业务对象 ID。
- 采购延期、检验不合格、BOM 差异等可创建项目事项；事项默认回填交付物/采购条目链接。
- 影响关键 WBS 或交期的采购问题可升级为风险，风险登记册可看到来源对象。
- 所有创建、更新、发布、同步、状态变更、取消和删除操作写入系统操作历史。

## 10. 文件存储、恢复与安全要求

- BOM、线缆清单的实际文件复用 `ProjectDocumentFile`、本地存储或 WebDAV；新模块只维护业务引用，不复制文件二进制。
- 上传延续现有项目文档大小限制与项目状态限制；已完成或已作废项目不再允许常规新增文件。
- Git 地址只保存地址和版本标识，不存储仓库账号、Token、密码或 SSH 私钥。
- 新表和新文件引用必须纳入项目级恢复预检查、全量备份和恢复映射；恢复前检查引用文件是否存在。
- 采购状态日志、已发布 BOM 版本和已下单记录为审计对象，不允许通过普通“撤销”抹去历史。

### 11.5 既有横向能力改造

- 在项目级恢复、备份序列化和预检查中加入新实体与文件引用。
- 在操作历史的实体显示名中加入“交付物”“材料版本”“采购条目”。
- 为新增模块接入现有模块历史快照与撤销/重做框架；采购状态日志不随普通撤销删除。
- 在项目执行 Gate 规则中预留“交付物验收”“关键采购合格”的检查项。
- 在项目助手可读数据源中增加交付和采购摘要；任何变更操作仍必须走白名单、权限和确认边界。

## 12. 实施顺序

### 阶段 A：领域与基础数据

1. 新增 Prisma 模型、手工迁移、领域枚举和接口。
2. 扩展项目关系、备份/恢复和操作历史类型。
3. 配置权限树、菜单入口和详情页导航占位。

**完成标准**：迁移可重复执行；项目创建、删除、备份、恢复不会遗漏新数据；无权限用户无法访问 API。

### 阶段 B：交付物清单与状态管理

1. 完成交付物清单表格和结构操作。
2. 完成软件 Git 地址与硬件样机/量产状态表单。
3. 实现状态机、必填校验、类型切换限制与模块历史。

**完成标准**：可以完整登记软件和硬件交付物，并在进入待评审时阻止缺失必备资料的记录。

### 阶段 C：材料版本与文件导入

1. 复用项目文档存储上传 BOM/线缆清单。
2. 完成 CSV/XLSX 导入预览、列映射和物料行维护。
3. 完成草稿、发布、替代版本规则。

**完成标准**：每个有效硬件资料能被定位到“交付物 + 阶段 + 清单类型 + 版本 + 原始附件 + 物料行”。

### 阶段 D：采购同步与采购执行

1. 完成采购条目表格和手工采购。
2. 完成 BOM/线缆同步预览、幂等匹配和已下单保护。
3. 完成状态机、数量金额校验、状态日志、WBS/预算关联。

**完成标准**：用户能从量产 BOM 生成采购条目，跟踪至到货、检验和关闭，并回溯至来源版本。

### 阶段 E：闭环整合与验收

1. 接入审批、协同、事项、风险和 Gate 检查。
2. 增加导出、空状态、移动端布局、审计和助手摘要。
3. 完成端到端测试与演示数据。

**完成标准**：演示项目可走通“交付物 → BOM 版本 → 采购 → 到货检验 → 交付验收”的完整链路。

## 13. 验收场景

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| AC-01 | 新建软件交付物 | 可填写名称、数量、单位、软件类型、外协方式；状态页要求 Git 地址 |
| AC-02 | 软件交付物提交待评审但未填 Git 地址 | 被阻止，显示明确行内提示 |
| AC-03 | 新建“有样机”的硬件交付物 | 状态页出现样机与量产两组 BOM/线缆资料卡 |
| AC-04 | 有样机硬件缺少样机线缆清单即待评审 | 被阻止，并定位缺失资料 |
| AC-05 | 上传量产 BOM 并按模板导入 | 原文件保存；可预览和编辑物料行；发布后形成版本 |
| AC-06 | 从量产 BOM 同步采购 | 建议采购数量正确等于单台用量 × 量产数量；来源可回溯 |
| AC-07 | 已下单采购条目对应的 BOM 发生改版 | 系统显示差异，不静默修改已下单数据 |
| AC-08 | 采购从下单到部分到货、检验、合格、关闭 | 每次状态转移写入日志，数量和金额校验正确 |
| AC-09 | 非授权用户直接调用写接口 | 返回禁止访问，不能仅依赖前端菜单隐藏 |
| AC-10 | 完整项目备份后恢复 | 交付物、状态、材料版本、文件引用、采购条目和状态日志完整恢复 |

## 14. 首期不纳入范围

- 不直接连接 Git 平台拉取提交、构建状态或代码权限；首期仅登记地址与版本标识。
- 不使用 OCR 自动识别 PDF/图片 BOM；结构化采购数据以模板导入或手工维护为准。
- 不替代 ERP、财务付款、发票、合同或仓储系统；本模块聚焦项目级采购执行跟踪。
- 不自动取消或覆盖已下单/已收货采购数据；变更必须以差异和人工决策处理。
- 不预设固定审批人或金额阈值，审批规则由现有审批流程配置决定。

## 15. 需要在实施前确认的业务参数

本方案已经可以开始基础实施；以下参数不阻塞数据模型，但应在阶段 D/E 前由业务方确认：

1. 是否默认把线缆清单也纳入“同步到采购”，还是每次由用户选择；本方案默认提供选择。
2. BOM 导入首期是否必须包含物料编码、厂家/品牌、税率和币种；本方案只强制名称、单位、单台/单套用量。
3. 采购下单审批的金额阈值、项目类型和审批链；本方案采用可配置流程。
4. 硬件交付物总数量是否始终等于“样机数量 + 量产数量”；本方案采用此校验，特殊备品可作为独立交付物登记。
5. 采购实际金额是否由项目经理维护，还是后续与财务/ERP 集成；本方案首期允许授权用户维护。
