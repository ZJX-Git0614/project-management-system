# 佳佳完整领域 Agent 升级计划

## Requirements Summary

- 将佳佳从“数据库问答 + 固定动作分发”升级为面向项目管理的领域 Agent。
- 保留现有账号权限、项目成员范围、Agent 授权模式和人工确认边界。
- 首个完整纵向切片必须支持：上传单个 MPP/XML/XLSX 计划文件，转换为系统可导入 Excel，并返回可下载文件。
- 能力问答必须来自服务端能力注册信息，不允许模型根据工具名称猜测“支持/不支持”。
- 动作规划应识别“输出、转换、整理成、做成”等自然表达，并把附件类型、数量和解析状态纳入决策。
- Agent 执行必须留下规划、动作、结果和错误证据，生成的计划文件需要重新解析校验。

## Acceptance Criteria

1. 用户上传一个状态为 READY 的 `.mpp`、`.xml` 或 `.xlsx` 文件并要求“按系统甘特任务格式输出”时，系统生成 `schedule.convert.file` 动作。
2. 在 `AUTO_APPROVE` 或 `FULL_ACCESS` 模式下，低风险转换动作自动执行并返回 `.xlsx` 下载地址；`REQUEST_APPROVAL` 模式下先展示确认卡片。
3. 输出工作簿可由 `parseGanttExcel` 重新解析，任务数与转换前一致，否则动作失败且返回明确错误。
4. “我给你一个 mpp 文件，你能帮我按照系统的甘特任务格式输出文件吗”必须被识别为能力/操作问题，不得回答“系统不支持 MPP”。
5. 没有上传附件时，助手明确提示支持的格式、下一步上传方式及不会直接写入项目进度；不得虚构已生成文件。
6. 多文件合并行为保持不变，仍要求至少两个附件。
7. 新工具继续受 `project-gantt:create` 权限、项目访问范围和 Agent 启用工具列表约束。
8. 单元和 API 路由测试覆盖精确原句、单附件转换、无附件能力问答、双附件合并及失败路径。

## Architecture Decision

- 使用服务端类型化能力目录作为单一事实来源，目录声明工具 ID、输入格式、附件数量、输出类型、风险等级和权限。
- 保留现有确定性动作解析作为快速、安全路径；模型规划器只在目录范围内做语义归一化。
- 将单文件转换与多文件合并共享解析、任务规范化、Excel 生成和生成后校验内核，但保留两个业务动作，避免语义和校验条件混淆。
- 不给内网助手开放通用 Shell 或任意文件系统访问；完整 Agent 指“可规划、可组合、可观察、可校验的项目管理领域工具”，而不是无边界桌面代理。

## Implementation Steps

1. 在 `src/lib/assistant-settings.ts` 扩展类型化工具目录，新增 `schedule.convert.file`，并确保旧配置可获得该默认工具。
2. 在 `src/lib/schedule-file-merge.ts` 抽取共享工作簿管线，新增单文件转换函数，保留多文件最小数量约束及生成后校验。
3. 在 `src/lib/assistant-actions.ts` 增加单文件转换意图、附件约束、权限映射、动作提议、文件产物和下载结果。
4. 在 `src/lib/project-assistant-model.ts` 扩展动作触发语义，并向规划器提供结构化输入/输出约束。
5. 在 `src/lib/assistant-manual.ts` 和使用手册中修正能力问题识别，让无附件的能力询问得到确定性真实说明。
6. 在聊天路由中记录 Agent 规划阶段和未形成动作的原因，逐步形成“观察 -> 计划 -> 执行 -> 校验 -> 结果”闭环。
7. 补充单元、路由和产物测试，再运行类型检查、Lint、相关测试和生产构建。

## Risks And Mitigations

- MPP 转换器在低配置 Windows Docker 环境不可用：继续使用镜像内 Java MPXJ，并把转换器错误原样归入动作失败证据。
- 旧数据库工具白名单缺少新工具：沿用向后兼容的默认工具迁移策略，并增加回归测试。
- 小模型输出不稳定：确定性规则优先，模型只返回受 JSON 和工具白名单约束的计划。
- 单文件转换误写项目：动作只生成附件产物，不直接导入或修改甘特任务。
- 大型 MPP 资源消耗：沿用 20 MB 上传限制、转换超时和最多 5 个会话附件限制。

## Completed Domain Agent Tracks (2026-07-29)

### 1. 全量工具契约化

状态：已实现。工具目录现统一声明版本、输入/输出 schema、权限、风险、幂等策略、重试策略和验收器；提议与执行入口均拒绝 schema 外参数。

- 为现有待办、甘特、事项、风险、导出、文档修订和计划分析工具补齐输入 schema、输出 schema、权限、风险、幂等策略和可重试错误类型。
- 管理后台、模型规划器、能力问答和服务端执行器只读取同一能力目录。
- 验收：目录中的每个启用工具都有契约测试，模型不能提交 schema 外参数。

### 2. 多步骤计划与续跑

状态：已实现基础闭环。模型规划支持最多 6 步 DAG，计划与步骤持久化；确定性计划工作流优先，中风险步骤逐步确认，已成功步骤不重复执行。

- 将模型规划结果从单个 `{toolId, command}` 扩展为最多 6 步的有向无环计划，每一步声明依赖的前序输出。
- 中风险写操作逐步确认；确认后从检查点续跑，不重复执行已成功步骤。
- 验收：“分析上传计划 -> 对比当前进度 -> 导出报告 -> 选定冲突转风险”能够保留同一计划轨迹并分阶段完成。

### 3. 观察、恢复与目标校验

状态：已实现。错误分为输入、权限、并发、暂时性依赖、业务规则、未知工具和验收失败；仅回放安全工具允许暂时性故障有限重试，输入失败进入待补充状态。

- 工具错误分为输入缺失、权限拒绝、并发冲突、暂时性依赖故障和不可恢复业务错误。
- 仅对暂时性故障做有界重试；输入缺失转为明确补充项，并在用户补充后续跑。
- 每个计划声明最终验收器，例如文件可重新导入、任务数一致、数据库状态已变化或导出文件可下载。
- 验收：任何 `SUCCEEDED` 计划都有可读取的验证证据，任何 `FAILED` 计划都有最后失败步骤和建议恢复动作。

### 4. 领域工作流组合

状态：已实现首批纵向切片。计划附件支持对比、报告、风险和整改待办组合；文档附件支持诊断、分段重写、缺失项保留、修订稿生成与下载；甘特写操作继续执行权限、数据变化和重新编号检查。

- 文档：读取 -> 结构诊断 -> 重写 -> 事实/缺失项校验 -> 生成修订稿。
- 计划：解析 -> 与当前甘特匹配 -> 差异/冲突/干涉分析 -> 报告 -> 风险/整改待办。
- 甘特：定位任务 -> 预览影响范围 -> 权限/并发检查 -> 修改 -> 重新编号和依赖校验。
- 验收：每条工作流至少包含正常、歧义、权限不足、数据变化和工具故障五类端到端用例。

### 5. 小模型评测与可观测性

状态：评测框架与本机实测均已完成。内置 24 条中文项目管理指令；`qwen3.5:4b` 动作选择 100%、`qwen3.5:9b` 95.8%，两者白名单违规均为 0。参数线索准确率分别为 81.0% 和 85.7%，因此生产链路继续执行确定性解析与 schema 复核。

- 建立中文项目管理指令集，覆盖同义表达、口语、省略、附件数量和多轮补充。
- 分开评估“意图选择准确率、参数准确率、执行成功率、目标校验通过率”，不以回答文采代替 Agent 能力。
- 目标：4B/9B 模型的确定性高频场景动作选择准确率不低于 95%，未经白名单复核的动作执行数为 0。
