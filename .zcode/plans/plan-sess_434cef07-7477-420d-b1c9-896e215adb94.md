# 项目执行阶段、Gate 与驾驶舱实施计划

## 已确认的业务边界

- **WBS 是唯一计划事实源**：任务、日期、工期、依赖、资源和实际进度只在 WBS 中维护；阶段不得保存第二份排期或进度。
- **阶段范围以 WBS 子树为主**：选择根 WBS 节点时，阶段自动包含其全部后代；仅当阶段确实跨多个分支时，才追加直接关联任务。
- **一期 Gate 采用可可靠计算的规则**：范围内末级任务、关联事项和关联风险；文档没有阶段级归属/发布状态，第一版只支持申请说明和审批意见中的人工证据，不作为自动条件。
- **驾驶舱保留现有 URL**：继续使用 `/projects/[projectId]?nav=execution`，把现有面板升级为“执行驾驶舱 + 阶段维护”，不创建破坏当前侧栏和项目上下文的新路由。

## 一期：阶段视图与健康度

### 1. 阶段范围模型和兼容迁移

- 扩展 `ProjectExecutionTask.relationType` 的领域语义：
  - 旧的 `PRIMARY` 兼容解释为 `DIRECT`。
  - 新增 `SUBTREE`，表示该关联任务是 WBS 根节点，运行时自动展开后代。
  - `DIRECT` 表示跨分支补充的单任务。
- 在 `src/lib/project-execution.ts` 新增范围解析函数：将阶段 links 与全量 WBS 标量构建为去重后的范围任务集合；计算统计时仅保留末级任务，防止同时关联父子任务造成进度重复计权。
- 进度按 `estimatedWorkHours` 加权；缺失工时时回退到 `durationDays * 7.5`。计划开始/完成则由有效范围任务的最早/最晚值实时汇总，并兼容 `T0+N` 相对排期。
- 新增幂等手工迁移 `prisma/manual-migrations/<日期>_project_execution_scope.sql`：将历史 `PRIMARY` 归一化为 `DIRECT`，并增加 `relationType` 查询所需索引。同步 Prisma schema 和数据库操作手册。
- 扩展 `src/domain/models.ts` 的阶段 DTO，显式返回直接范围、子树范围、有效末级任务数、加权进度和范围预警。

### 2. 阶段健康度服务

- 新建纯函数服务 `src/lib/project-execution-health.ts`，输入阶段有效范围及预加载的 WBS、事项、风险数据，输出 `HEALTHY / AT_RISK / OFF_TRACK / UNKNOWN` 与有限条可解释原因。
- 规则优先级：
  - `OFF_TRACK`：存在已逾期未完成末级任务、负浮动/无效依赖等排期错误、或关键任务已逾期。
  - `AT_RISK`：存在未完成关键任务、近临界任务、开放高风险、逾期/阻塞事项、计划开始临近但尚未准备完成。
  - `UNKNOWN`：阶段无有效范围或仅有无法比较的相对 T0 排期。
  - 其余为 `HEALTHY`。
- 健康度永远是派生结果，不回写 `ProjectExecution.status`；现有状态保留为人工工作流状态。
- 风险与事项只在调用方拥有 `risk-register:view`、`weekly-items:view` 时进入聚合和响应，避免通过 WBS 权限间接泄露其他领域数据。

### 3. 阶段 API 与 UI 改造

- 新建 `GET /api/projects/[id]/execution-cockpit`：一次性以最小字段读取项目、阶段/范围、WBS、事项、风险、Gate 摘要；服务端内存构造范围和健康度，避免按阶段 N+1 查询，初始响应只返回摘要、计数和有限预警证据。
- 调整 `src/app/api/projects/[id]/executions/route.ts` 与 `[executionId]/route.ts`：接收并校验 `scopeLinks`（`SUBTREE`/`DIRECT`），兼容旧 `taskIds`；禁止提交父子重复范围；阶段已放行后限制破坏性范围调整。
- 调整 `src/components/project-execution-panel.tsx`：
  - 首页改为驾驶舱摘要和阶段时间线，按健康度突出当前/异常阶段。
  - 阶段详情展示有效范围、任务完成/逾期/关键任务计数、风险和事项摘要及跳转入口。
  - 维护弹窗改用现有 `hierarchical-multi-select.tsx`：根节点以 `SUBTREE` 选择，直接任务作为补充选择，清晰标注两种语义。
  - 阶段编辑不再把“完成”作为普通下拉选项直接保存；完成由二期 Gate 放行写入。
- 更新导航文案为“项目执行驾驶舱”，保留内部 `execution` key 与 URL；修复 `permissions.ts` 中对该项目详情导航的权限规则缺口，继续沿用现有 `project-gantt:*`，避免一次性改变全部角色矩阵。

### 4. WBS 删除、恢复和项目恢复

- 在 `src/lib/gantt-task-service.ts` 的删除预览、删除快照、恢复和重做中纳入阶段关联：删除 WBS 前返回受影响阶段和活跃 Gate；快照保存 `ProjectExecutionTask`，恢复任务时恢复 links，不再因 FK 级联静默丢失阶段范围。
- 在 `src/lib/project-restore.ts` 的项目级选择性恢复表和顺序中纳入 `ProjectExecution`、`ProjectExecutionTask`，确保阶段数据不会在项目恢复时丢失。
- 阶段范围变化后在操作历史中记录受影响阶段和变更原因。

## 二期：阶段出口 Gate

### 1. Gate 数据与审批集成

- 新增 Prisma 模型：
  - `ProjectExecutionGate`：阶段出口 Gate、状态、申请/放行时间、发起人与决策摘要、范围快照 hash、WBS revision。
  - `ProjectExecutionGateCriterion`：关键任务、事项、风险三类条件的配置和最近评估结果。
  - Gate 通过 `executionId` 关联阶段；审批实例使用现有 `ApprovalWorkflowInstance` 的确定性 businessId，不复制审批状态机。
- 新增幂等迁移及项目恢复支持；Gate 数据以审批实例和 Gate 记录共同保存长期审计证据。
- 在 `src/lib/approval-workflow.ts` 增加 `PROJECT_EXECUTION_EXIT_GATE`、中文标签、确定性 `approvalBusinessIdForProjectExecutionExitGate`、默认可配置审批工作流（项目经理审批）。
- 在 `src/lib/approval-business-registry.ts` 注册 Gate handler：
  - `validateStart` 和 `apply` 均重新计算条件，拒绝信任客户端或旧 payload。
  - payload 包含 executionId、范围 hash、ganttRevision、评估快照和申请说明。
  - `apply` 仅在范围/版本及条件仍满足时将 Gate 标为放行、将阶段标为完成，并写操作历史；不写入第二份计划数据。
- 新增阶段 Gate API：获取评估、发起放行申请、查看 Gate 历史。审批中心继续复用现有处理、退回、撤销和 effect 重试 UI。

### 2. 一期 Gate 条件

- 范围内的全部末级任务进度为 100%。
- 阶段范围关联的事项没有未完成、逾期或阻塞项。
- 阶段范围关联的风险没有未关闭高风险。
- Gate 申请说明必填；可选选择项目文档作为人工证据，但第一版不把它们作为自动放行规则。
- WBS revision、阶段范围、关联事项或风险在审批期间变化时，审批 effect 拒绝执行并提示重新评估/重新申请。
- 已通过 Gate 后范围发生关键变化时标记为“放行后范围变更”，要求重新评估；豁免/有条件放行在首版暂不开放，避免先建立难以审计的例外路径。

### 3. 权限与审计

- 在权限树新增 `project-execution:gate-request`；阶段普通编辑仍复用 `project-gantt:edit`。
- 审批动作继续复用 `approval-center:process/cancel/retry`，不会让阶段负责人绕过审批。
- Gate 申请、退回、审批效果、范围变更、WBS 删除影响和恢复均记录 `OperationHistory`；审批实例/assignment/effect 保存完整决策链。

## 三期：完整执行驾驶舱

- 在一期驾驶舱基础上加入项目总览：当前阶段、下一 Gate、预测日期、阶段健康度时间线。
- 按权限渐进加入项目级和阶段级异常队列：关键路径延误、资源冲突、开放风险、逾期事项、Gate 缺口。
- 绩效权限存在时，复用 `calculateEarnedValue` 计算阶段/项目 SPI、CPI 等指标；无权限或数据不足时不显示，不能用空值伪造健康结论。
- 跨项目资源冲突不在页面自动刷新时计算；用户显式发起资源诊断时才复用已有资源分析服务，保留现有脱敏规则。
- 提供阶段评审包/周报导出：仅汇总已有任务、风险、事项、Gate 和审批证据，不创建新的业务事实。

## 测试与验证

- 新增 `project-execution-health.test.ts`：子树展开、父子去重、工时加权、绝对/相对日期、逾期、关键路径、事项和风险健康度矩阵。
- 新增阶段范围/API 路由测试：权限拒绝、旧 `taskIds` 兼容、`SUBTREE`/`DIRECT` 校验、跨项目任务拒绝、完成状态绕过拦截。
- 扩展 WBS 删除与恢复测试：受影响阶段预览、链接快照、恢复和重做。
- 二期新增 Gate 条件、重复发起幂等、审批期间范围变更、审批 effect 重试和完成状态拦截测试。
- 新增驾驶舱 API/组件测试：无阶段、加载/错误、权限裁剪、健康度显示与有限预警响应。
- 每期执行 `npm run typecheck`、相关 Vitest 测试、`npm run lint`，最后执行完整 `npm test`；涉及迁移时在一次性测试数据库上验证新装、升级和项目恢复路径。

## 实施顺序

我会按一期、二期、三期顺序实施，每期在通过类型检查、lint 和完整测试后再进入下一期。首先完成一期的范围语义、健康度、驾驶舱读 API/UI，以及删除/恢复保障；这一步本身就能让现有阶段模块从“手工分组标签”变为有决策价值的阶段视图。
