# 删除每月事项与 Plane 借鉴能力实施计划

日期：2026-07-06

## 目标

删除当前系统中的“本月事项”模块，并在后续产品设计中不再把每月事项作为独立模块考虑。后续进度/事项管理主线收敛为：

```text
项目进度管理：项目进度甘特图 + 本周事项
项目风险管理：风险登记册
项目成本管理：项目预算管理
新增增强能力：保存视图、详情抽屉、事项收集池、项目文档、模块/阶段管理
```

## 当前证据

- 左侧导航存在“本月事项”：`src/components/app-shell.tsx:298`
- 每月事项页面存在：`src/app/monthly-items/page.tsx:7`
- 每月事项 API 存在：`src/app/api/monthly-items/route.ts:23`
- 每月事项单条 API 存在：`src/app/api/monthly-items/[id]/route.ts:28`
- Prisma 中存在 `Project.monthlyItems` 和 `MonthlyItem` 模型：`prisma/schema.prisma:42`, `prisma/schema.prisma:160`
- 项目详情 API 返回 `monthlyItems`：`src/app/api/projects/[id]/route.ts:19`
- 总览/驾驶舱统计查询 `monthlyItem`：`src/app/api/overview/route.ts:30`, `src/app/api/dashboard/route.ts:21`
- 权限树与路由规则包含 monthly-items：`src/lib/permissions.ts:109`, `src/lib/permissions.ts:254`
- 待办类型包含 `MONTHLY_ITEM_OVERDUE`：`src/domain/enums.ts:35`, `src/lib/constants.ts:51`
- seed 数据创建本月事项和本月事项逾期待办：`prisma/seed.ts:271`, `prisma/seed.ts:300`
- `ItemPanel` 当前同时服务 monthly/weekly：`src/components/item-panel.tsx:35`

## 需求总结

1. 删除“本月事项”作为用户可见模块。
2. 删除每月事项页面、API、权限、导航和统计入口。
3. 后续规划不再考虑每月事项，改以“本周事项 + 甘特图 + 事项收集池”承接事项管理。
4. 删除时避免破坏“本周事项”，因为 `ItemPanel` 是月/周复用组件。
5. 保留历史操作记录的兼容展示能力，避免旧数据中的 `MONTHLY_ITEM` 字符串导致页面显示异常。
6. 数据库处理需要明确：删除模型会使历史 MonthlyItem 数据不可再访问；如需要保留历史，可先导出或迁移到周事项/事项收集池。

## 实施方案

### 阶段 1：退役每月事项

1. 导航与权限
   - 从 `src/components/app-shell.tsx` 删除“本月事项”菜单项。
   - 从 `src/lib/permissions.ts` 删除 `monthly-items` 权限节点和 `/monthly-items` 路由规则。
   - 检查管理员默认权限/seed 权限中是否还有 monthly key，删除对应默认授权。

2. 页面与 API
   - 删除 `src/app/monthly-items/page.tsx`。
   - 删除 `src/app/api/monthly-items/route.ts`。
   - 删除 `src/app/api/monthly-items/[id]/route.ts`。
   - 确认 `/monthly-items` 访问不再出现在导航和权限路由里。

3. 数据模型
   - 从 `prisma/schema.prisma` 删除 `Project.monthlyItems` 关系。
   - 删除 `MonthlyItem` 模型。
   - 从 `src/domain/models.ts` 删除 `MonthlyItem` interface。
   - 从 `OperationHistory.entityType` 联合类型中删除 `MONTHLY_ITEM`，或保留为历史兼容类型。建议保留展示兼容，不再产生新记录。
   - 生成 Prisma Client，并创建迁移或同步 schema。

4. 统计和项目详情
   - 从 `src/app/api/projects/[id]/route.ts` 删除 `monthlyItems` include 和响应字段。
   - 从 `src/app/api/overview/route.ts` 删除 monthly 统计，调整返回结构和前端引用。
   - 从 `src/app/api/dashboard/route.ts` 删除 monthly 统计，调整返回结构和前端引用。
   - 检查 `src/app/overview/page.tsx` 和任何 dashboard 页面是否展示 monthly 指标，删除对应卡片。

5. 待办类型和常量
   - 从 `TodoType` 删除 `MONTHLY_ITEM_OVERDUE`。
   - 从 `TODO_TYPE_LABEL` 删除“本月事项逾期”。
   - 检查 todo 生成逻辑是否还有 monthly overdue。
   - 对已有历史 Todo 数据：如果数据库中已有 `MONTHLY_ITEM_OVERDUE`，短期可保留 label 兼容，长期可用一次性脚本转为 `CUSTOM` 或删除。

6. 周事项组件收敛
   - 将 `ItemPanel` 从 `monthly | weekly` 的双模式收敛为周事项专用，或保留泛型但删除 monthly 分支。
   - 建议短期保留组件名但只支持 weekly，减少一次性改动。
   - 中期可重命名为 `WeeklyItemPanel`，让代码语义更干净。

7. seed 和 README
   - 删除 `prisma/seed.ts` 中本月事项 seed。
   - 删除本月事项逾期待办 seed。
   - 更新 `README.md` 中模型数量和功能描述。

### 阶段 2：引入高价值 Plane 借鉴能力

优先级从高到低：

1. 保存视图
   - 适用模块：本周事项、风险登记册、项目预算、甘特图。
   - 保存内容：筛选条件、排序、显示列、分组方式。
   - 推荐先做本周事项和风险登记册。

2. 详情抽屉
   - 适用模块：风险登记册、本周事项、甘特任务。
   - 列表只保留高频字段，长文本、历史、关联信息放右侧详情。
   - 优先解决当前表格横向拥挤问题。

3. 事项收集池
   - 替代每月事项的长期承接能力。
   - 用户先提交“未归类事项”，项目经理确认后转为：
     - 本周事项
     - 风险登记册
     - 甘特任务
     - 自定义待办
   - 状态：待确认、已转入、已驳回、暂缓、重复。

4. 项目文档 / Pages
   - 项目背景、会议纪要、决策记录、验收标准统一沉淀。
   - 文档中产生的行动项可以转入事项收集池或本周事项。

5. 模块/阶段管理
   - 将甘特图的“任务类别”升级为“项目阶段/模块”。
   - 模块可有负责人、起止日期、状态、说明、关联任务和风险。

## 原型方案

### 原型 A：本周事项 + 保存视图

定位：先把本周事项打磨成高效率的执行列表。

```text
┌────────────────────────────────────────────────────────────┐
│ 本周事项                         [视图: 我的待办 v] [保存视图] │
├────────────────────────────────────────────────────────────┤
│ 筛选：项目 v  状态 v  健康度 v  负责人 v  关键词 ________       │
├────────────────────────────────────────────────────────────┤
│ □ 事项ID  关联任务  事项名称       负责人  状态    截止  健康度 │
│ □ W001    Task003   完成联调验证   成员B    进行中  07-10  有风险 │
│ □ W002    Task007   输出验收材料   李四    待开始  07-12  未知   │
└────────────────────────────────────────────────────────────┘
```

适合第一阶段后马上做，因为它接住了删除每月事项后的“短周期事项管理”。

### 原型 B：风险登记册 + 详情抽屉

定位：让风险登记册从“宽表”变成“紧凑列表 + 深度详情”。

```text
┌──────────────────────────────────────────────┬────────────────────┐
│ 风险登记册               [选择] [删除] [新增] │ 风险详情             │
├──────────────────────────────────────────────┤ 风险名称：...        │
│ □ R001  供应商延期  高  处理中  成员C  07-20  │ 分类：采购           │
│ □ R002  需求变更    中  识别中  赵六  07-15  │ 触发条件：...        │
│ □ R003  成本超支    高  跟踪中  成员B  07-25  │ 应对措施：...        │
│                                              │ 活动记录：...        │
└──────────────────────────────────────────────┴────────────────────┘
```

适合第二优先级做，能显著改善复杂表格的专业感和可读性。

### 原型 C：事项收集池

定位：承接临时事项、会议行动项、客户反馈，替代“每月事项”的泛化收纳作用。

```text
┌────────────────────────────────────────────────────────┐
│ 事项收集池                         [新增事项] [批量处理] │
├────────────────────────────────────────────────────────┤
│ 状态：待确认 v  来源：会议/客户/内部 v  项目 v             │
├────────────────────────────────────────────────────────┤
│ □ I001  客户要求增加验收清单字段   来源: 客户   待确认      │
│ □ I002  会议提出采购延期风险       来源: 会议   待确认      │
├────────────────────────────────────────────────────────┤
│ 处理动作：转为本周事项 | 转为风险 | 转为甘特任务 | 驳回 | 暂缓 │
└────────────────────────────────────────────────────────┘
```

这是最有 Plane Intake 价值的部分。建议在删除每月事项后作为下一轮核心新增。

### 原型 D：项目文档 / 决策记录

定位：补齐当前系统没有文档承载层的问题。

```text
┌──────────────────────────────────────┬─────────────────────────┐
│ 项目文档                              │ 文档内容                 │
├──────────────────────────────────────┤                         │
│ 会议纪要                              │ # 2026-07-06 周会       │
│ 决策记录                              │ - 决定删除每月事项       │
│ 验收标准                              │ - 行动项：... [转事项]   │
│ 客户沟通                              │                         │
└──────────────────────────────────────┴─────────────────────────┘
```

适合在事项收集池后做，因为文档里的行动项可以直接进入收集池。

### 原型 E：项目模块/阶段

定位：把甘特任务类别升级成可管理的阶段/模块。

```text
┌─────────────────────────────────────────────────────────────┐
│ 项目阶段/模块                         [新增模块]              │
├─────────────────────────────────────────────────────────────┤
│ 模块名称    负责人  起止日期           状态      关联任务 风险 │
│ 设计阶段    成员B    07-01 ~ 07-10      进行中    8      1    │
│ 联调阶段    李四    07-11 ~ 07-20      未开始    12     2    │
└─────────────────────────────────────────────────────────────┘
```

这个功能会让甘特图、风险、本周事项之间的关系更稳定，但需要先清理现有任务类别口径。

## 推荐路线

```text
第一步：删除每月事项
第二步：本周事项增强为执行中心
第三步：风险登记册详情抽屉
第四步：事项收集池
第五步：项目文档
第六步：模块/阶段管理
第七步：保存视图扩展到所有表格
```

如果希望更快看到产品效果，可将“保存视图”和“详情抽屉”并行设计，但代码实现建议仍按模块分步做，避免一次改动过大。

## 验收标准

1. 左侧导航不再出现“本月事项”。
2. 权限配置中不再出现“本月事项”相关权限。
3. 前端无 `/monthly-items` 可见入口。
4. 构建时不存在 `prisma.monthlyItem` 类型引用。
5. 项目详情、总览、驾驶舱不再返回或展示 monthlyItems 指标。
6. 本周事项功能不受影响，增删改查、下拉保存、批量删除和导出仍可用。
7. 风险登记册、预算、甘特图不受影响。
8. `npm run typecheck` 通过。
9. `npm run lint` 通过。
10. `npm run build` 通过。

## 风险与处理

1. 数据丢失风险
   - 删除 `MonthlyItem` 模型会使历史每月事项数据被数据库迁移删除。
   - 处理：执行前导出 `MonthlyItem` 表，或确认这些数据可以废弃。

2. 复用组件误伤
   - `ItemPanel` 同时服务 monthly/weekly。
   - 处理：删除 monthly 分支时重点回归本周事项。

3. 历史操作记录显示异常
   - 历史记录中可能仍有 `MONTHLY_ITEM`。
   - 处理：展示层短期保留 `MONTHLY_ITEM -> 本月事项（历史）` 映射，不再产生新记录。

4. 权限脏数据
   - 用户角色中可能仍保存 monthly 权限 key。
   - 处理：读取权限时忽略未知 key；可追加一次清理脚本。

## 验证步骤

1. 静态搜索：
   - `rg "monthlyItem|MonthlyItem|monthly-items|本月事项|MONTHLY_ITEM"`
   - 预期只剩历史兼容说明或无业务引用。

2. 类型检查：
   - `npm run typecheck`

3. Lint：
   - `npm run lint`

4. 构建：
   - `npm run build`

5. 浏览器回归：
   - 登录系统。
   - 确认导航无本月事项。
   - 打开项目进度管理、本周事项、风险登记册、项目预算、项目列表。
   - 对本周事项执行新增、编辑、下拉选择即保存、批量删除、导出。

## 后续不再考虑项

- 不再设计“本月事项”独立模块。
- 不再保留“本月事项逾期”待办类型。
- 不再在驾驶舱单独统计“本月事项完成率”。
- 后续如需要月度管理，应通过“保存视图 + 日期筛选 + 周事项汇总”或“项目文档/月度复盘”实现，而不是恢复本月事项模块。
